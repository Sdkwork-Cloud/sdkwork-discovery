# sdkwork-discovery 行业专业注册中心对齐实施计划

## 目标

将 sdkwork-discovery 对齐行业专业注册中心（Consul/etcd/Nacos/ZooKeeper）能力，覆盖性能、安全、实时性、事务、高可用、降级六大维度。

---

## Phase 1: P0 - 生产就绪（4-6周）

### 1.1 Watch Event GC
**问题**: `events Vec` 和 `discovery_watch_event` 表无限增长

**方案**:
- `WatchEventStore` 新增 `gc_watch_events(before_revision, max_deletes)` 方法
- Actor 增加 GC 定时器（`event_gc_interval_ms`）
- 基于 revision 差值清理，适配所有存储后端

**文件**:
- `crates/sdkwork-discovery-storage-contract/src/watch_event_store.rs`
- `crates/sdkwork-discovery-storage-memory/src/watch.rs`
- `crates/sdkwork-discovery-storage-sqlite/src/sql.rs` + `store.rs`
- `crates/sdkwork-discovery-storage-postgres/src/sql.rs` + `store.rs`
- `crates/sdkwork-discovery-core/src/control_plane.rs`
- `crates/sdkwork-discovery-rpc/src/actor.rs`
- `crates/sdkwork-discovery-config/src/model.rs`

### 1.2 CAS 乐观并发控制
**问题**: 注册/更新无条件覆盖，防并发写丢失

**方案**:
- `RegisterInstanceCommand` 增加 `expected_revision: Option<u64>`（None=旧行为）
- `ReportInstanceStatusCommand` 增加同样字段
- 新增 `DiscoveryError::Conflict` 变体
- Memory: 直接比对 revision
- SQL: `UPDATE ... WHERE revision = ?`

**文件**:
- `crates/sdkwork-discovery-contract/src/registry.rs` + `error.rs`
- `crates/sdkwork-discovery-storage-memory/src/registry.rs`
- `crates/sdkwork-discovery-storage-sqlite/src/sql.rs` + `store.rs`
- `crates/sdkwork-discovery-storage-postgres/src/sql.rs` + `store.rs`
- `crates/sdkwork-discovery-rpc/src/codec.rs` + `error.rs`
- `proto/sdkwork/discovery/common/v1/discovery_types.proto`

### 1.3 标签过滤发现
**问题**: `DiscoverInstancesQuery` 不支持 metadata 过滤

**方案**:
```rust
pub struct LabelFilter { key: String, op: LabelFilterOp, value: String }
pub enum LabelFilterOp { Eq, NotEq, In, Exists }
```
- Memory: Rust filter chain
- SQL: `json_extract(metadata_json, '$.key')` / `jsonb -> key`

**文件**:
- `crates/sdkwork-discovery-contract/src/registry.rs`
- `crates/sdkwork-discovery-storage-memory/src/registry.rs`
- `crates/sdkwork-discovery-storage-sqlite/src/sql.rs` + `store.rs`
- `crates/sdkwork-discovery-storage-postgres/src/sql.rs` + `store.rs`
- `crates/sdkwork-discovery-rpc/src/codec.rs`
- `proto/sdkwork/discovery/common/v1/discovery_types.proto`

### 1.4 权重/优先级路由
**问题**: `weight`/`priority` 字段已存在但发现时未使用

**方案**:
```rust
pub enum DiscoverSortBy { InstanceId, Priority, Weight, WeightedRandom }
```
- Priority: `ORDER BY priority ASC, weight DESC`
- WeightedRandom: 查询后 Fisher-Yates weighted shuffle

**文件**: 同 1.3 文件列表

### 1.5 主动健康检查
**问题**: 仅有被动 self-report，实例宕机后依赖 lease 过期才发现

**方案**:
- 新建 `crates/sdkwork-discovery-health-checker/` crate
- 支持 HTTP/TCP/gRPC 三种探测类型
- `RegisterInstanceCommand` 增加 `health_check: Option<HealthCheckConfig>`
- Actor 集成探测定时器，连续失败达阈值 → `NotServing`
- 新增 migration: `ALTER TABLE discovery_service_instance ADD COLUMN health_check_json TEXT`

**文件**:
- `crates/sdkwork-discovery-health-checker/` (新 crate)
- `crates/sdkwork-discovery-contract/src/registry.rs`
- 各存储实现 + `actor.rs` + `config/model.rs`
- 新 migration 文件

## Phase 2: P1 - 竞争力提升（3-4周）

### 2.1 请求级限流
- 令牌桶算法，`crates/sdkwork-discovery-rpc/src/rate_limiter.rs`（新）
- Actor 入口处限流，超限返回 `Status::ResourceExhausted`

### 2.2 熔断器
- 三态（Closed/Open/HalfOpen），`crates/sdkwork-discovery-rpc/src/circuit_breaker.rs`（新）
- 新增 `DiscoveryError::Unavailable`
- Actor dispatch 中 wrap store 调用

### 2.3 只读模式降级
- 依赖 2.2 熔断器状态
- 写操作被拒绝，读操作继续（可能返回 stale 数据）

### 2.4 批量注册/注销
- Proto: `BatchRegisterInstanceRequest/Response`
- `RegistryStore` 新增 `batch_register_instances` 方法

### 2.5 事件压缩
- 同一资源保留最新 N 条事件，删除中间事件
- SQL: `ROW_NUMBER() OVER (PARTITION BY resource_id ORDER BY revision DESC)`

---

## Phase 3: P2 - 生态完善（2-3周）

### 3.1 多节点集群
- 无状态多实例 + Postgres HA
- Watch 跨实例传播: Postgres LISTEN/NOTIFY 或 Redis Pub/Sub

### 3.2 命名空间隔离
- `NamespaceConfig` 配额（max_instances/max_services）
- `NamespaceStore` trait + 权限控制

### 3.3 持久实例模式
- `RegisterInstanceCommand` 增加 `persistent: bool`
- `expires_at_ms = u64::MAX`，跳过 expiry scan

### 3.4 配置加密
- AES-256-GCM 加密敏感配置值
- `create_config_draft` 加密存储，`retrieve_effective_config` 解密返回

## 实施顺序

```
Phase 1 (P0)
  1.5 Watch GC ──→ 1.1 CAS ──→ 1.3 Label Filter ──→ 1.4 Weight/Priority ──→ 1.5 Health Check

Phase 2 (P1)
  2.1 Rate Limit ─┬─→ 2.3 Read-Only ──→ 2.5 Event Compaction
  2.2 Circuit ────┘
  2.4 Batch (可并行)

Phase 3 (P2)
  3.3 Persistent ──→ 3.2 Namespace ──→ 3.4 Encryption ──→ 3.1 Cluster
```

## 验证策略

每个 Phase 完成后运行：
```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Phase 1 验收:
- [ ] CAS: 并发注册返回 Conflict
- [ ] Label Filter: metadata 查询三种存储均正确
- [ ] Weight/Priority: discover 结果按指定排序
- [ ] Watch GC: 事件表大小受控
- [ ] Health Check: 实例宕机后自动标记 NotServing

Phase 2 验收:
- [ ] 限流: 超阈值返回 ResourceExhausted
- [ ] 熔断: 存储故障快速失败，恢复后自动关闭
- [ ] 批量: 性能优于逐个调用

Phase 3 验收:
- [ ] 多节点: 两实例共享数据库，watch 跨实例传播
- [ ] 命名空间: 配额限制生效
- [ ] 持久实例: 不参与 expiry scan
